# Contract: テーマが公開するトークン面

**Date**: 2026-09-18 | **Feature**: [spec.md](../spec.md)

コンポーネントがテーマに対して依存できる面(公開契約)を定める。ここに載っていない経路で
見た目の値を得てはならない。

## 公開されるもの

| 区分 | 参照経路 | 内容 |
|---|---|---|
| 配色 | テーマの palette | semantic な役割名(本文色・補足色・背景色・面の色・境界線色・強調色・成功/警告/エラー) |
| テキストスタイル | テーマの typography | 画面見出し / 節見出し / 本文 / 補足 / UIラベル(data-model.md の役割と一致) |
| 余白 | テーマの spacing 関数 | 基準8px。段階は 4 / 8 / 16 / 24 / 32 / 48 px |
| 角丸 | テーマの shape | 公式 `border-radius-*` の写像 |
| 影 | テーマの shadows | 公式 `elevation-1..8` の写像 |

## 契約規則

1. **生値の禁止**: コンポーネントは色コード(`#...`)および `px` 付き寸法をリテラルで書かない。
   例外は `src/app/theme/` 配下(トークンの定義元)と、テスト・ストーリー内の検証用の値のみ。
   違反は Lint で検出される(FR-003 / SC-005)。
2. **semantic 優先**: 配色は役割名で参照する。primitive の色を直接参照してよいのは
   テーマ定義内に限る。
3. **一次ソースの単一性**: 公式トークンの値をプロジェクト側で上書き・改変しない。
   必要なのが「別の値」である場合は、公式のどのトークンを選ぶかで解決する(原則IV / INV-4)。
4. **後方互換**: 役割名の削除・意味変更は spec の改訂を要する。追加は随時可能。
5. **グラフの配色**: グラフの系列色もこの palette から取得する。ただし非視覚的代替
   (表形式・テキスト要約)は既存のまま維持する(FR-010 / 原則VII)。

## 検証(いずれも `[自動]`)

- テーマ定義の値を1箇所変更すると、その値を参照する全画面の表示に反映される(SC-004)。
- 対象コンポーネント内に色コード・`px` 寸法のリテラルが存在しない(SC-005)。
- 本文のテキストスタイルが 16px 以上・行高 1.5 以上(INV-2 / FR-012)。
- 余白が定義済み6段階に一致する(INV-3 / FR-007)。
